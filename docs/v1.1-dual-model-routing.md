# V1.1 dual-model routing

`qwen_route_v1` centralizes model identity and deterministic task routing:

| Tier | Default model | Tasks |
| --- | --- | --- |
| Fast | `qwen3.5:4b` | Watchlist screening, signal trigger, simple summary and explicit Fast requests |
| Smart | `qwen3.5:9b` | Assistant, signal explanation, Daily Brief, event analysis, deep research and explicit Smart requests |

User preference is `fast`, `smart` or `auto`. Auto maps the server-owned task enum to a tier and returns version, requested preference, selected tier/model and reason in stream metadata and health. The client cannot extend the task/model set. Existing scheduler/analysis defaults use the centralized Fast constant; model work remains serial.

There is no silent cross-tier substitution. If the selected exact model is missing or Ollama is unavailable, the request reports unavailable. This preserves the Smart path without pretending a lower tier produced a Smart answer. The local resource guard may defer model scans but never kills Ollama, ComfyUI or another GPU process.
