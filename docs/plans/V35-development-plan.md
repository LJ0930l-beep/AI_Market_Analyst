## 基线审计结论

1. `core/trading/entry_economics.py` 使用 `Decimal` 计算手续费、滑点、数量精度、扣费后净盈亏比及止损风险。V34 Gate AI 路径、`ExecutionGateway` 的开仓边界和 `core/replay/ai_template_runner.py` 的回放入口都调用这套逻辑。
2. Gate 的 `MARGIN_ONLY` 名称不代表只检查保证金：网关会将预计止损风险交给 `AccountLedger.reserve_margin_only`，该事务重新读取当前保存的策略和最新可用的 Gate 权益快照，并拒绝超出 `risk_per_trade_pct` 的提案。没有新鲜权益或风险证据时失败关闭。
3. 生产 `FIXED_NOTIONAL` 取保存的 2,000 USDT 目标；资金/名义上限不满足会拒绝。模型动态名义路径存在按保证金上限调整数量的行为，V35 研究模式不得复用这种静默缩量路径。
4. Gate 回放入口先按完整委托计算经济性，但模拟账户后续仍可能按可用保证金压低数量。V35 将只为 Gate 研究回放增加“必须原量提交”的守卫，使这种不一致在账户状态变更前明确拒绝；普通模拟器既有的通用容量行为保持不变。
5. V25 脱敏样本没有当前账户权益，也不携带可证明为当时或当前 Gate 交易规则的完整合约元数据。历史结论必须标为反事实代理；样本中的 `ACCEPTED`/`FILLED` 记录是模拟事件，不能表述为 Gate 接受委托或真实成交。

## 计算口径

设账户权益为 `E`，策略单笔风险百分数为 `r`（当前配置按百分点解释，例如 `0.15` 表示 0.15%），风险预算 `B = E × r / 100`。

对多头或空头，先按订单类型应用保守入场/止损/止盈滑点，再按合约大小和数量步长计算：

- 止损风险 = 数量 × 合约大小 × 不利入场至止损价差 + 入场和止损两腿的保守手续费。
- 净盈亏比 = 扣除两腿保守手续费与不利滑点后的目标净收益 / 止损风险。
- 固定模式保留提案的 2,000 USDT 目标；数量按交易所步长向下量化后，超风险、低于净盈亏比门槛、资金/保证金不足或违反合约限制均拒绝，不因风险预算缩小名义金额。
- 风险预算模式从 `B` 反推最大可下单数量/名义金额，并将其作为 AI 提案上限。AI 提案必须自行满足上限；计算器只报告容量和拒绝原因，不替模型改小订单。
- 固定名义最低权益的风险下限为 `预计止损风险 / (r / 100)`。若缺少可用保证金或策略保证金上限，只能报告风险预算下限，不能声称完整资金可行。

## BUILD 工作项

- 增加纯函数诊断层：返回提案原值、价格与数量精度、成本、止损风险、风险预算、净盈亏比、保证金估计、最低风险权益、可行状态和稳定拒绝代码。
- 支持 `FIXED_NOTIONAL` 与 `RISK_BUDGETED_NOTIONAL` 两种研究模式。两者共用 Gate 已有的经济计算函数；新增预算反推不得读取未来行情或调用外部服务。
- 为 Gate 回放委托添加精确数量要求。模拟账户若只能接受较少数量，则在创建订单或占用风险前拒绝，生产 Gateway 不变。
- 编写只读取脱敏 V25 样本的生成器。明确记载数据 SHA-256、成本假设、合约代理、权益场景及模拟/真实成交边界。
- 输出 `reports/v35-feasibility/feasibility-summary.json` 和 `reports/v35-feasibility/v25-counterfactual-comparison.json`。仓库忽略 `reports/`，这些文件本地保留，不强制提交。

## VERIFY 覆盖

- 多空、限价/市价、不同权益和止损距离、手续费/滑点、合约精度、保证金不足、无效/非有限输入。
- 两种模式均用同一成本/风险函数；超预算一律拒绝；风险预算模式不得静默下调原提案。

- 完整测试运行前后按失败 node ID 对照；既有失败独立列出，不删测、不降断言。
