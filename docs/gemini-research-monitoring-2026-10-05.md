# 五套策略研究监控与验收

## 目标与边界

以独立验证的扣费后平仓胜率至少 50% 为研究目标，同时检查净收益、回撤与交易活跃度。不是未来胜率保证，不通过强制下单、缩小亏损样本或只挑行情达到目标。暂定至少 30 笔完整平仓才讨论通过；30 只是最低样本要求，不足以保证统计显著性。

报告同时给出 Wilson 95% 描述性区间，区间下界不足 50% 时不能称为有充分统计支持；交易相关性、市场制度变化和多次筛选并未被这个区间覆盖。优化区永远不作为独立验证。零平仓时胜率未知。

24 轮没有开仓提案或连续 24 次 WAIT 触发诊断，检查缺失条件是否合理、后续触发时是否行动。这是诊断阈值，不是强制开仓规则。跟踪原始模型提案、有效开仓动作、挂单接受和成交数量，区分模型主动等待、契约错误、执行拒绝和限价未成交。

## 本次修复

旧 v4 实验的 23 次调用中，21 次 WAIT，另有两次 ETH 开多原始提案因缺少名义金额、杠杆和订单类型而失败，其中一次有效期 3600 秒超出契约 60–1800 秒范围。没有任何 Gate 订单。

新提示明确要求 AI 自填交易参数。只有具备授权标的、已选方向、有限正数价格和有效置信分数的 OPEN，且错误属于漏字段或有效期范围时，允许同一冻结事实下的一次模型补齐。已有方向、标的、入场、止损、止盈及已填金额、杠杆均不可改变。未知引用、其他价格错误和网络失败不能进入该补齐路径；补齐再次失败则本轮无交易。程序不填写交易金额。

v4 保留审计；新代码运行于 `reports/gemini-year-research-v5-20261005`，不会把不同代码版本的收益混算。先运行最多 50 次真实调用作执行检查，确认模型契约和成交路径后再扩大至 1008 次优化研究。研究不触碰真实账户与生产策略。

## 查看与继续

每 15 分钟的本对话监控已经创建。状态不变时安静，失败、实质进展或完成时通知。监控应先核对 Win32 实际进程及命令行，不能把 `RUNNING` 文件当作任务仍活着的证明。

```powershell
python scripts/monitor_gemini_research.py --directory reports/gemini-year-research-v5-20261005
python reports/gemini-year-research-v4-20261005/export_decisions.py --directory reports/gemini-year-research-v5-20261005
```

上面两个命令只读取本地研究数据库，不调用模型或交易所。监控指标写入 `observation.json`，决策页面写入 `decisions.html`。它们是快照，需重新生成后刷新。

当前进程退出后才评估恢复。优化结束后生成候选修改，在未参与优化的验证区与最终测试区检验。样本不足、胜率不达标、过度等待未解释、净收益非正或执行错误未解决均不能宣称完成。
