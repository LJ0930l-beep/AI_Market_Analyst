# AI Market Analyst V1.2 completion report

Date: 2026-08-31
Release: `1.2.0` / API Phase 7 / SQLite schema `12`
Scope: Crypto Smart Monitoring, TradingView-compatible chart display and Windows desktop packaging

## Delivered scope

V1.2 is implemented as one local Windows x64 desktop release. Tauri 2 owns the visible shell and a packaged PyInstaller FastAPI sidecar. The current-user NSIS installer places the program under `%LOCALAPPDATA%\Programs\AI Market Analyst`; the sidecar creates the separate `%LOCALAPPDATA%\AI Market Analyst` data/log/backup/runtime layout, initializes additive schema 12, serves loopback-only API routes and is stopped through its exact owned process tree. The AppData database is preserved across reinstall/uninstall.

The backend supports public Binance REST and combined WebSocket market data for BTCUSDT, ETHUSDT and SOLUSDT. It stores bounded 15m/1h bars, quote/realtime freshness and reconnect state, uses REST backfill after disconnects, and records closed 15m bars exactly once. `MonitoringPolicy` is explicit opt-in. The FastAPI sidecar owns a bounded `monitoring_runtime_v1` worker with explicit start/resume/pause/stop lifecycle, enabled-policy-only ingestion, backoff and local alert events; it continues while the window is hidden. Python owns `trigger_policy_v2`, trigger fingerprints, cooldown, indicators, risk levels, validator decisions and all ledger writes.

Smart OpportunityAnalysis calls the explicit `qwen3.5:9b` tier only. Valid output is persisted into Prediction/Outcome/Calibration-compatible evidence; invalid output is retained as quarantine evidence with an error. The qwen3.5:4b tier is used for explicit cached news translation. Original English evidence remains complete and `numeric_guard` validates numeric/date/price preservation.

The React/TypeScript UI uses typed English/Chinese catalogs, responsive terminal styling, Lightweight Charts for candles/volume/overlays, alert deep links, and a Tauri native-notification bridge. TradingView is not a backend provider and no proprietary chart library is shipped.

## Security and lifecycle decisions

- No exchange account, secret, wallet, broker, private key or real-order path exists.
- Packaged sidecar binds to `127.0.0.1:18765` by default; `AIMA_SIDECAR_PORT` is an explicit alternate loopback port for isolated smoke/test runs. Tauri CSP and shell permission are scoped to the app sidecar.
- Only the exact spawned sidecar PID/tree is stopped. Ollama, ComfyUI and unrelated processes are untouched.
- Monitoring is stopped by default; auto-start and resume are independent false defaults and cause no startup analysis or scan. A startup resume is accepted only after an explicit prior user start was durably recorded.
- The tray exposes live Monitoring state, Pause/Resume, terminal, Settings, backend restart and Exit. A close request while the runtime is active always hides to tray and emits a one-time continuation notice.
- Windows login autostart is registered through the official Tauri autostart plugin only when explicitly enabled; uninstall cleanup removes the exact Run/StartupApproved values.
- Legacy database movement is explicit and validated. Migration is additive/idempotent; data is stored in `%LOCALAPPDATA%`.
- Fixture fallback is disabled in packaged/live smoke runs. Browser fixtures are identified as UI-only evidence.

V1.2 contracts include `crypto_realtime_v1`, `monitoring_policy_v1`, `monitoring_runtime_v1`, `trigger_policy_v2`, `opportunity_analysis_v1`, `chart_data_v1`, `chart_annotations_v1`, `news_evidence_v1` and `localized_news_artifact_v1`. ## Repair Gate evidence

The production rebuild is reproducible from a clean checkout with the following command; it is intentionally run from `src-tauri` because that is the documented Tauri project directory:

```powershell
cd D:\RJ\codex\ai-market-analyst\src-tauri
cargo +stable-x86_64-pc-windows-gnu tauri build --target x86_64-pc-windows-gnu
```

Tauri invokes the repository-root `beforeBuildCommand`, and `scripts/build-tauri.ps1` resolves child scripts from `$PSScriptRoot` and fails on any child non-zero exit. The resulting package contains the built React assets, both target-tagged sidecars, the Tauri shell and the NSIS installer; the installed runtime does not require npm, Vite or Node.

## Honest limitations

Public endpoints can be rate-limited, disconnected or stale. Local Ollama latency/GPU capacity and model answer quality are not release SLAs. RSS translation depends on source content and numeric guard can reject an otherwise readable translation. Windows PushNotification event-log delivery was observed for the installed notification smoke, but the automation surface did not retain a durable visual toast or directly observe the OS click. The official Tauri notification Actions API is documented for mobile platforms; therefore V1.2 does not claim ordinary Windows toast-action observation and uses the safe in-app Alert Center route fallback when click delivery is unavailable. The release is Windows x64 and uses loopback port `18765` by default, with an explicit local override for isolated runs. There is no remote/cloud deployment or distributed scheduler.
