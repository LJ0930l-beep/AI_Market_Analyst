# AI Market Analyst V1.2 user guide

## Install and launch

Run `src-tauri\target\x86_64-pc-windows-gnu\release\bundle\nsis\AI Market Analyst_1.2.0_x64-setup.exe` and choose the current-user install. The default program directory is `%LOCALAPPDATA%\Programs\AI Market Analyst`; runtime `data`, `logs`, `backups` and `runtime` directories are kept separately under `%LOCALAPPDATA%\AI Market Analyst`. Launch **AI Market Analyst** from the Start menu or run `ai-market-analyst.exe` directly.

The desktop shell starts one owned loopback FastAPI sidecar at `http://127.0.0.1:18765`, waits for its health response and then loads the UI. Starting the executable again focuses the existing window. If the port is occupied, the shell remains open in a desktop-owned degraded state and does not touch the other process. Tray actions include opening the terminal, showing live Monitoring state, pausing/resuming the real sidecar worker, opening Settings, restarting only the owned backend and **Exit**. Exit stops the exact owned sidecar tree; it does not stop Ollama, ComfyUI or other processes.

Install the local models separately when Smart analysis or news translation is needed:

```powershell
ollama pull qwen3.5:4b
ollama pull qwen3.5:9b
```

No cloud account, exchange account, secret or API key is required.

For a source rebuild, run the official Tauri command from the `src-tauri` directory:

```powershell
cd D:\RJ\codex\ai-market-analyst\src-tauri
cargo +stable-x86_64-pc-windows-gnu tauri build --target x86_64-pc-windows-gnu
```

This command invokes the repository-root build wrapper and produces the NSIS installer; the installed app does not require npm, Vite or Node.js.

## Data and migration

The active database is `%LOCALAPPDATA%\AI Market Analyst\data\market_analyst.sqlite3`. Runtime evidence and backups remain outside the installed program files so an upgrade or uninstall does not silently remove the research ledger.

V1.1 checkout data is imported only by an explicit command while the desktop app is closed:

```powershell
python -B scripts\import_legacy_database.py `
  --source data\market_analyst.sqlite3
```

An optional `--destination` can name a validated database file. The command refuses ambiguous paths and reports whether the destination was created or already exists. It never recursively deletes the source.

## Monitoring workflow

Open **Monitoring** and choose BTCUSDT, ETHUSDT or SOLUSDT. Every policy starts disabled. Enable only the symbols you want, review the 15m primary / 1h context and trigger settings, then press **Save**. Press **Start monitoring** to explicitly start the sidecar-owned worker. **Pause**, **Resume** and **Stop** have real lifecycle effects; the same actions are available from the tray. **Run now** remains a separate explicit one-cycle scan and is not the background worker.

The sidecar-owned `monitoring_runtime_v1` obtains public Binance REST data, maintains a bounded combined WebSocket stream for enabled policies, backfills after reconnects and wakes on closed 15m bars. It never scans a disabled policy and caps active monitoring at 50 symbols. The Python service computes indicators and `trigger_policy_v2`, deduplicates by bar-close fingerprint, applies cooldowns, and records valid Smart analyses. The qwen3.5:9b model is used for OpportunityAnalysis only. Missing model, malformed JSON, invalid levels or unsafe WAIT output is shown as an unavailable/quarantined result, not substituted with qwen3.5:4b.

Valid directional results are saved to the existing Prediction ledger and can flow through Outcome and Calibration as the normal local research lifecycle. Nothing is sent to an exchange. The validator, not the model or browser, owns entry/stop/TP1/risk-reward and financial arithmetic.

The default runtime state is stopped. Normal startup does not perform a scan. In Settings, **Auto Start** uses the official Windows login registration and is off by default; it starts only the app/tray. **Resume Monitoring on Startup** is a separate opt-in and only resumes a previously user-started runtime. Turning Resume on does not authorize a first scan.

## Charts and evidence

Asset Detail provides **15m** and **1h** Lightweight Charts with candles, volume, Python indicators/levels and trigger annotations. The chart library is a display dependency only. Its bars come from the app’s public-data API; TradingView is not contacted as a backend data source.

The News panel preserves the full English title, summary, publisher and publication timestamp. **Translate** is an explicit action using qwen3.5:4b. The cached Chinese artifact contains the original evidence, model metadata and a `numeric_guard` result. If a number/date/price/percentage is lost, the translation is rejected instead of silently edited.

## Availability and safety

`fresh`, `stale`, `degraded` and `unavailable` are meaningful runtime states. Public-provider rate limits, network interruption, RSS availability and local Ollama capacity can prevent a fresh result. Retry/backfill evidence is visible; fixture data is not enabled by the packaged app. If the window is hidden, the sidecar continues monitoring and sends new deduped alert events through the always-mounted desktop bridge; a native notification permission failure degrades to the in-app Alert Center/banner.

If monitoring is active, clicking the window **X** always hides to the tray and shows a one-time notice that monitoring continues. Pause or Stop first if you want the sidecar to stop; when monitoring is inactive, X follows the close-to-tray preference. Tray **Exit** is the explicit full exit action.

The product is a public-data research/monitoring terminal. It has no private exchange API, broker, wallet, private-key, real-order, cloud notifier or automatic trading function.
