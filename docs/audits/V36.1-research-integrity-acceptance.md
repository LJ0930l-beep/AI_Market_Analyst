## 修改文件与原因

- `scripts/run_pa_decision_quality_v36.py`：离线模式允许传入 `--model-id` 作为缓存键元数据；仍拒绝 `--caller`，并且没有模型调用注入路径。
- `core/replay/pa_decision_quality_v36/validation.py`：新增版本绑定的分析复验、证据引用白名单检查、模型身份对照；V35 A0 使用冻结的动作 Schema 快照及其哈希版本，A1/A2 使用 V36 Schema 版本。
- `core/replay/pa_decision_quality_v36/experiments.py`：把分析 Schema 版本纳入实验提示和精确缓存身份；缺少新版本字段的旧精确缓存不能冒充匹配。
- `core/replay/pa_decision_quality_v36/runner.py`：分别记录请求模型 ID 与响应实际模型 ID；缺少实际 ID 或响应畸形时标记 `UNVERIFIED`，绝不回填请求 ID。A0/A1/A2 缓存命中均重新校验 Schema 和证据引用；无效缓存不进入风险预检或生命周期指标。缓存声明的 Schema 版本原样保留，供 review 独立复验。
- `core/replay/pa_decision_quality_v36/review.py`：复验缓存和完成响应，不信任 runner 存储的验证结论；区分缓存键命中、有效缓存分析和身份已匹配的模型决策。无效分析不进入决策统计或结果连接，并单列跳过的结果数。
- `tests/v36/test_cli.py`、`tests/v36/test_runner.py`、`tests/v36/test_review.py`：增加离线零调用、A1/A2 精确匹配、有效/无效证据与 Schema、模型身份匹配/不符/未验证、畸形响应和指标一致性测试。
- `docs/audits/V36.1-research-integrity-acceptance.md`：记录本次范围、验证、失败归类和残余风险。

没有修改 `core/trading/`、Gate 执行、生产资金参数、V35 风控实现、V25 原始样本或既有 V25/V33/V34/V35/V36 报告。

## 差异说明

`CACHE_MATCH` 仍只表示缓存键精确命中，不等于分析有效。review 以实验版本对应的 Schema、当前因果证据引用和最小状态快照重新验证后，分别计数 `cache_matches`、`valid_cache_analyses`、`verified_cache_model_decisions`、`invalid_cache_analyses`。实际响应 ID 匹配才进入模型决策和结果连接；请求 ID 不再被用作实际身份的替代值。

FIXED_NOTIONAL/RISK_BUDGETED_NOTIONAL 研究定义、V35 经济预检和生产默认值均未更改。本修复不评价交易策略胜率或收益。

## 遗留风险与限制

- `actual_model_id` 是调用适配器报告的响应身份。当前研究框架没有独立 provider 签名或远端收据，故 `MATCHED` 证明字段相等，不证明模型权重或远端执行的密码学真实性。
- 缺 Schema 版本、实际模型 ID 或可用证据集合的旧缓存会按 fail-closed 处理，不能计为有效缓存决策。
- 仓库全量仍有 100 项基线失败，尽管本次数量未增加；它们覆盖策略模板、执行、模型身份、API/监控等既有模块，不能据本报告视为已修复。
- 未做历史 V25 反事实回放；V25 样本和历史结论保持原样。
