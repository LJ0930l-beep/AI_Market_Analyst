# AI Market Analyst V1.2.1 Completion Report

Date: 2026-09-03
Status: `DEVELOPER_COMPLETE`; final acceptance repair delivered.

## Outcome

V1.2.1 closes the Production Usability Repair against the existing V1.2 stage without rewriting V1.1/V1.2 history. The release is a Tauri 2 Windows x64 application with built React assets and an owned PyInstaller FastAPI sidecar. Production startup requires neither npm, Vite nor Node.js. API/package version is `1.2.1`; SQLite migration is additive/idempotent through schema `13`.

The sidecar owns a real `monitoring_runtime_v1` worker. It is inert until the user explicitly starts or resumes it, processes enabled MonitoringPolicy rows only, maintains public REST/WS state and bounded backfill/freshness, submits each 15m closed bar through Python's exactly-once trigger ledger, calls Smart `qwen3.5:9b` only after a trigger state change, persists validated opportunity/alert evidence, and continues while the window is hidden. Pause and stop terminate work; startup resume requires the independent explicit preference. Monitoring, auto-start and resume are all false by default.

## Desktop ownership and safety

- Rust selects the first free loopback port in `18765..18828`, constructs all sidecar arguments, checks instance/ownership identity and never adopts or kills a foreign listener.
- The owned-sidecar watchdog exposes degraded state and supports bounded restart of only the owned child. The WebView has no shell spawn capability.
- Tray state is sourced from the live runtime. The menu supplies terminal, status, pause/resume, Settings, restart-owned-backend and Exit actions. Active X always hides to tray with a one-time notice; inactive X follows the preference and can explicitly exit.
- Official Tauri Windows autostart registration is OS-authoritative. It starts only the application/tray. Resume monitoring is separate and default off.
- Uninstall removes program files and autostart registration but preserves `%LOCALAPPDATA%\AI Market Analyst`. Upgrade and reinstall retain the data.
- No account, exchange secret, private key, broker, real order, funds, cloud notification or proprietary TradingView asset exists. Ollama and unrelated processes are outside application ownership.

## Market, model and UI delivery

Public Binance REST/WS supports BTCUSDT, ETHUSDT and SOLUSDT with 15m/1h cached bars, reconnect/freshness and bar-close exactly-once. Lightweight Charts renders only app-supplied public data and Python-owned support/resistance, watch-zone, stop, target, trigger and outcome annotations. Smart opportunities require real `qwen3.5:9b`; unavailable or invalid Smart output remains unavailable/quarantined and is never represented as 4B. Explicit news translation uses `qwen3.5:4b`, retains complete original/structured evidence, caches artifacts and applies strict numeric/date guard semantics.

All routes remain typed bilingual. The deterministic E2E suite covers 15 route states in English/Chinese at desktop/mobile sizes, 30 axe scans and 30 page-overflow checks. Those fixtures prove UI contracts only. Separate live evidence proves public providers and local models.

When there are no Prediction rows, Signals is no longer an empty ledger shell. It shows read-only deterministic market evidence for BTCUSDT, ETHUSDT, SOLUSDT and watchlist symbols, live monitoring state, `trigger_policy_v2` evidence, the latest validated opportunity when one exists, transparent missing/degraded reasons, and an explicit per-symbol link to the market/analysis workflow. Loading Signals does not call Qwen and does not create a Prediction; model work remains an explicit user action on the asset route.
