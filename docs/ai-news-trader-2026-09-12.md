# AI 自拟策略机器人：新闻 + 技术面

白茶确认的产品路线是「AI 自拟策略，再按固定风控执行」。本次直接沿用现有账户、执行网关、风险账本及持仓保护体系，统一机器人主入口。没有覆盖开发前已有的未提交修复，也没有启动真实资金账户。

## 实际运行流程

1. 控制台向 `/v2/ai-session/start?account_id=...` 提交所选账户；暂停、恢复和终止也使用同一账户范围。
2. 现有运行时提供会话代次、独占租约、行情流和 PositionGuardian。AI 模式下传统策略循环停止独立做单。
3. 下一个 15 分钟 UTC 边界，协调器先核验账户和模型，刷新公开 Gate K 线与新闻。首次运行仍要求现有校准流程成功（默认至少 500 根有效历史 15m 样本）。校准不是收益回测。
4. Python 为每个标的计算 EMA20、简单平均 RSI14 / ATR14、20 根成交量比和支撑阻力。只使用当前时刻已经可知的已收盘 K 线，拒绝缺口、未来数据、非有限数和未经验证的历史来源。
5. 给 Qwen 9B 提供最近 24 根 15m / 1h 蜡烛、指标、报价、新闻、持仓、近期决策与精简策略候选。指标实际由最多 64 根连续 K 线计算。首次补取历史的 `RECONSTRUCTED_LATE` 只有在 `available_at <= 当前周期时刻` 时可使用。
6. AI 自拟策略并在标的间选择本轮一个动作：`OPEN_LONG`、`OPEN_SHORT` 或 `WAIT`；已有持仓支持 `HOLD`、减仓、平仓和收紧止损。
7. JSON Schema 本地验证始终执行；Ollama 不支持原生语法约束时，兼容 JSON 模式也不能绕过验证。仅允许一次修复重试。
8. 开仓先验证技术面、新闻引用、当前入场价格及扣费后盈亏比，再由现有 ExecutionGateway / RiskEngine 计算仓位、保留预算并执行。每轮保留输入哈希、模型指纹、策略计划、分析和执行回执。

## AI 输出内容

`strategy_plan` 包含策略名称、交易逻辑、入场条件、退出条件；`timeframe_analysis` 包含 15m 和 1h 分析；`news_context` 包含新闻影响和摘要。还需输出置信分数、失效条件、证据引用；新开仓必须提供入场价、入场区间、止损、止盈和风险比例。

自然语言交易逻辑由 AI 判断；程序验证可计算的价格区间与硬风险，不会把自然语言条件误称为已经通过机械规则验证。等待未来突破、回踩或事件确认时，模型应返回 WAIT，下一轮重新判断。当前没有将自由文本条件注册为未来自动触发订单。

新闻和历史模型文本都是不可信数据，不能更改系统指令、账户范围或固定风控。引用必须来自本轮实际冻结证据。开仓至少引用选中标的的报价、技术快照和一条 48 小时内可知新闻；新闻中性可以交易，新闻缺失不能编造依据。缺少新开仓证据不妨碍已有持仓的减仓/保护。

## 固定开仓边界

| 项目 | 当前默认 |
|---|---|
| 模型 | 本机 `qwen3.5:9b`，无 4B 或云端替代 |
| 单笔风险 | 最多权益的 0.25%，沿用更严格的底层风控 |
| 组合 / 单簇风险 | 1% / 0.5% |
| 日亏损熔断 | 1.5% |
| 杠杆 | 最多 3 倍，省略时 1 倍 |
| 净盈亏比 | 至少 2，包含手续费及滑点 |
| AI 置信分数 | 至少 70；主观分数，未经胜率校准 |
| 入场条件 | 当前价和计划入场价均在 `entry_zone` 内 |
| 盘口 | 远端账户需观测成本和深度；数量超过观测深度则阻断 |
| 推理 | 独立 16K 上下文、1800 输出 token、单次 HTTP 55 秒、一次受限修复 |
| 并发 | 每个协调器单周期、单模型任务；未结束的超时任务阻止后续堆积 |

限价区间使用 AI 提供的真实区间。成本估计使用已观测 20 档盘口的最差价格范围，并标识为估计；它不保证最终成交价。执行网关仍会重新执行自身时效、保护、风险和账户检查。

```powershell
python -m pytest -q
cd web

npm run lint

cd ..

```

新增测试覆盖无固定策略触发的 AI 自拟策略开仓、真实本地 PAPER 账本、新闻缺失/跨币种/未来/伪造引用、条件不满足、成本后盈亏比、非有限值、超风险/超杠杆、时序缺口，以及不把非法模型响应伪装成「模型未调用」。控制台测试验证所选账户的启动/暂停请求和 JSON 回执。

真实联调使用公开 Gate 行情、RSS 新闻和本机 Qwen 9B，临时数据库随测试结束清理，不读取私有凭证。记录路径为 `evidence/ai_news_strategy_smoke.json`。已观测真实模型返回带策略、技术面、新闻引用的 WAIT；没有为满足测试而强行产生交易。本测试不覆盖完整桌面启动/校准调度，也不证明盈利能力、回测表现或实盘订单成功。

## 客户端与兼容性

源码构建不会自动替换已安装的旧客户端。桌面外壳嵌入前端资源，需同时更新桌面 EXE 和 sidecar；只重建网页不能更新已安装 UI。现有 `scripts/sync-client.ps1` 是安装同步入口，会停止自有客户端，应在检查当前持仓保护与会话状态后由操作者执行。

`qwen-market-scans` 保留为兼容的只读研究 API；交易控制台已不使用它，研究扫描状态不会再冒充交易会话状态。旧的直接引擎兼容调用保留历史契约；生产协调器总是绑定 `ai_news_technical_v1` 开仓门禁。

本次设计参考 NOFX 的「策略提示 + 市场上下文 + 结构化决策 + 模型外风控」流程，没有复制其交易资金参数或替换本项目网关。参考：[NOFX 策略模块](https://github.com/NoFxAiOS/nofx/blob/dev/docs/architecture/STRATEGY_MODULE.md)、[NOFX 提示指南](https://github.com/NoFxAiOS/nofx/blob/dev/docs/prompt-guide.md)。
